# План тестування сервісу «Операційний звіт» (Команда 8)

## 1. Мета тестування

Перевірка коректності роботи сервісу формування операційного звіту платформи, відповідності обчислень формулі `healthScore`, коректності валідації вхідних даних та визначення статусів системи (`STABLE`, `DEGRADED`, `CRITICAL`).

## 2. Об'єкт тестування

Консольна програма C++17 (`src/main.cpp`), що реалізує структури `OperationsSummary`, валідатор `validateSummary`, функції обчислення `calculateOnlinePercent`, `calculateHealthScore` та класифікатор `classifyPlatform`.

## 3. Обов'язкові категорії та тестові сценарії

Згідно з технічним завданням, підготовлено 5 тестових сценаріїв, які охоплюють усі необхідні категорії:

1. **TC-8.1 (Типовий коректний сценарій):**
   * **Категорія:** Типовий коректний сценарій.
   * **Мета:** Перевірити розрахунок відсотка активних пристроїв, показника здоров'я та призначення статусу `STABLE` за стандартних робочих параметрів.
   * **Вхідні дані:** `devices = 20`, `online = 18`, `criticalSignals = 1`, `overloadedNodes = 0`, `openIncidents = 2`, `criticalIncidents = 0`, `availability = 99.5`, `recovered = 1`.
   * **Очікуваний результат:** Валідація успішна (`true`); `onlinePercent = 90.0%`; `healthScore = 81`; `status = STABLE`; список ризиків містить відключені пристрої, критичні сигнали та відкриті інциденти.

2. **TC-8.2 (Мінімальне допустиме значення / Запобігання діленню на нуль):**
   * **Категорія:** Мінімальне допустиме значення / Спеціальний ризик.
   * **Мета:** Перевірити стійкість програми при мінімальних граничних значеннях (0 пристроїв) та відсутність помилки ділення на нуль.
   * **Вхідні дані:** `devices = 0`, `online = 0`, `criticalSignals = 0`, `overloadedNodes = 0`, `openIncidents = 0`, `criticalIncidents = 0`, `availability = 0.0`, `recovered = 0`.
   * **Очікуваний результат:** Валідація успішна (`true`); `onlinePercent = 0.0%` (без crash / zero division); `healthScore = 100`; `status = STABLE`.

3. **TC-8.3 (Точне граничне значення статусу):**
   * **Категорія:** Точне граничне або порогове значення.
   * **Мета:** Перевірити роботу класифікатора на точній межі статусу `STABLE` (`healthScore = 80`).
   * **Вхідні дані:** `devices = 10`, `online = 6`, `criticalSignals = 0`, `overloadedNodes = 0`, `openIncidents = 0`, `criticalIncidents = 0`, `availability = 95.0`, `recovered = 1`.
   * **Очікуваний результат:** Валідація успішна (`true`); `offlineDevices = 4` (штраф 20); `healthScore = 80`; `status = STABLE`.

4. **TC-8.4 (Некоректний діапазон / Суперечливі дані):**
   * **Категорія:** Некоректний тип або діапазон (Негативний тест).
   * **Мета:** Перевірити, що валідатор відхиляє суперечливі дані, коли кількість онлайн-пристроїв перевищує загальну кількість (`online > devices`), і не пошкоджує стан програми.
   * **Вхідні дані:** `devices = 10`, `online = 15`, `criticalSignals = 0`, `overloadedNodes = 0`, `openIncidents = 0`, `criticalIncidents = 0`, `availability = 90.0`, `recovered = 1`.
   * **Очікуваний результат:** Валідація повертає `false`; програма виводить `"Invalid data!"` та повертається до головного меню без обчислень.

5. **TC-8.5 (Спеціальний ризик: нижня межа healthScore та статус CRITICAL):**
   * **Категорія:** Спеціальний ризик сервісу / Обмеження діапазону (Lower clamp).
   * **Мета:** Перевірити роботу алгоритму обмежувача (clamping) при критичній кількості відмов, коли сума штрафів перевищує 100 балів, а також присвоєння статусу `CRITICAL`.
   * **Вхідні дані:** `devices = 10`, `online = 0`, `criticalSignals = 5`, `overloadedNodes = 5`, `openIncidents = 10`, `criticalIncidents = 5`, `availability = 45.0`, `recovered = 0`.
   * **Очікуваний результат:** Валідація успішна (`true`); розрахований штраф = 180, початковий score = -80; обмежувач виставляє `healthScore = 0`; `status = CRITICAL`.
